## 不会执行的情况

1. **任一 item 为 `None`**：line 3–4 的 `if invalid(item): return False` 从循环体内部直接返回，跳过 line 6。这是 README（`README.md:11`）标注的该 fixture 的"hidden fact"。CFG 佐证：`return False` 节点 `cnode:d8405223…`（路径 `…/for_statement[0]/block[2]/if_statement[0]/block[1]/return_statement[0]`）有一条 `kind: "return"` 边直达函数 exit 节点 `cnode:4ba10bdf…`，绕过 finalize 调用点。

2. **line 6 之前任何异常向外传播**：函数没有 `try/finally`，finalize 不是保底调用，所以以下都会跳过 finalize：
   - `save(item)` 抛异常（line 5）；
   - `invalid(item)` 抛异常（line 3）；
   - `items` 不可迭代（如 `process(None)` 在 line 2 的 `for` 处抛 `TypeError`），或迭代器中途抛异常（生成器）；
   - `KeyboardInterrupt` / `SystemExit` 等。
   
   注意：这一条**不在**分析层 CFG 的建模范围内——`src/provenlattice/analysis_cfg.py:36-39` 把 `try_statement`、`raise_statement` 等列为 `FORBIDDEN_CONSTRUCTS`，CFG 只建模结构化控制流（if/for/break/continue/return），不含异常边。所以 CFG 的"唯一跳过路径是 return False"是对**结构化控制流**的断言，异常路径是它不表达的另一类真实跳过途径。

3. **平凡情况**：`process` 从未被调用（本仓库内确实无调用方，它是对外入口）；或 `items` 是永不终止的迭代器——循环不退出，finalize 永不执行。

## 小结（按发生条件）

| 情况 | finalize 是否执行 |

| 循环正常穷尽（含空 `items`） | 是（必然） |
